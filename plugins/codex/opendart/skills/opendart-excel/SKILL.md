# OpenDART 재무제표 Excel 생성 스킬

사용자 요청 예: "삼성전자 2022년 연결재무제표 엑셀로 만들어줘"

원문 처리(다운로드·문서 선택·파싱·Excel 생성·검증)는 MCP 서버의
`create_financial_workbook` 도구가 전부 수행한다. 이 스킬은 검색으로
접수번호를 정하고, 도구를 한 번 호출하고, 결과 파일을 전달한다.

## 사용 흐름

### 1. 요청 파싱
- 추출: **회사명**, **사업연도**, **기간**(연간/반기/분기), **범위**(연결 `consolidated` / 별도 `separate`).
- 회사명이나 사업연도가 없거나 모호하면 사용자에게 확인한다.
- 회사 별칭을 정식 회사명으로 확정할 수 없으면 사용자에게 확인한다.
- 기간이나 연결/별도가 모호하면 사용자에게 확인한다. 임의로 기본값을 선택하지 말 것. 연도만 말했으면 **사업보고서(연간)**로 처리한다.
- Excel 요청인지 불명확하면 출력 형식을 확인한다.
- 여러 항목이 모호하면 한 번에 질문하고, 명확한 항목은 다시 묻지 않는다.

### 2. corp_code 확인
`get_corp_codes`로 회사명 또는 종목코드를 검색해 `corp_code`를 얻는다.
후보가 여러 개면 사용자에게 확인한다.

### 3. 접수번호(rcept_no) 결정
`search_disclosures`로 요청 기간의 정기보고서를 찾는다.

- 파라미터: `corp_code`, `bgn_de`/`end_de`(사업연도+1년 범위, 예: 2022년 → `20230101`~`20231231`), `pblntf_detail_ty="A001"`(사업보고서).
- `report_nm`에 `"사업보고서 (YYYY.12)"`가 포함된 공시를 선택하고 `rcept_no`를 얻는다.
- **결산월이 12월이 아니면** `report_nm`의 연도가 사업연도와 어긋난다. 3월 결산 회사의 2024 사업연도 3분기는 `분기보고서 (2023.12)`이다. 확신이 없으면 `get_company_info`로 `acc_mt`를 확인하고, 검색 결과 제목을 직접 대조해 고른다.
- 같은 사업연도 공시가 여러 건이면(`[기재정정]` 포함) **최종 정정본**을 사용한다. 단, 정정 재제출본에는 감사보고서 첨부가 빠져 있을 수 있으므로(정정 대상이 아닌 첨부는 다시 안 붙이는 경우가 흔함), 첨부 부재 오류가 나면 그 이전 제출본(최초 제출본 포함)의 `rcept_no`로 소급한다.
- **검색 결과 0건이면**: `pblntf_ty="F"`(외부감사관련)로 재검색한다 — 비상장 외감법인은 정기보고서 없이 감사보고서만 단독 공시된다.
- 그래도 0건이면 임의로 다른 연도 공시를 대체하지 말고, 사용자에게 사유 후보와 함께 안내하고 다른 기간을 쓸지 확인한다: 제출 시기 미도래(사업보고서는 결산 후 90일 이내 제출), 신규상장(상장 전 연도), 미제출·제출지연 등.

### 4. 워크북 생성 — `create_financial_workbook` 1회 호출

```
create_financial_workbook(
    rcept_no="20250319000665",
    scope="consolidated",
    output_dir="<현재 작업의 쓰기 가능한 워크스페이스 경로>",
    output_name="SK하이닉스_2024_연결재무제표.xlsx"
)
```

- `rcept_no`: **검색 결과 값을 그대로** 쓴다. 지어내지 않는다.
- `scope`: `consolidated` 또는 `separate`.
- `output_dir`: 현재 작업의 writable workspace를 그대로 전달한다. 경로를 임의로 만들지 않는다.
- `output_name`: 스킬이 정한다. 권장 형식:
  - `SK하이닉스_2024_연결재무제표.xlsx`
  - `SK하이닉스_2024_별도재무제표.xlsx`
  - `SK하이닉스_2024_반기_연결재무제표.xlsx`
- `use_body`: 기본값 `false`. 아래 오류 대응 규칙에 해당할 때만 `true`로 재호출한다.

성공 반환 예:

```json
{
  "ok": true,
  "rcept_no": "20250319000665",
  "scope": "consolidated",
  "source_title": "연결감사보고서",
  "used_body": false,
  "company": "에스케이하이닉스 주식회사",
  "workbook": "C:/Users/user/output/SK하이닉스_2024_연결재무제표.xlsx",
  "verification": { "ok": true, "statements": 4, "notes": 36, "hyperlinks": 82 }
}
```

- `company`는 선택된 문서에서 추출한 회사명이다. 넘긴 `output_name`이 실제 문서와 맞는지 확인용으로 쓰고, 파일명 생성에는 쓰지 않는다.
- 동일 이름 파일이 이미 있으면 서버가 `SK하이닉스_2024_연결재무제표 (1).xlsx`로 저장한다. 반환된 `workbook` 경로를 **그대로** 사용자에게 전달한다.

### 5. 결과 전달
검증에 성공한 최종 Excel만 사용자에게 전달한다. `verification` 요약(재무제표 수,
주석 수, 하이퍼링크 수)을 함께 알려도 된다.

## 오류 대응

**`audit_attachment_not_found`** — 공시 안에 감사·검토보고서 첨부가 없다.
반환된 `documents`(문서 제목 목록)를 보고 보고서 종류로 판단한다. `use_body`는
기본값 그대로 두고 다음을 먼저 시도한다.

- 사업보고서·반기보고서: 법령상 감사·검토가 의무라 첨부가 반드시 존재한다. 정정 재제출본에서 빠진 경우이므로 **같은 사업연도의 이전 제출본** `rcept_no`를 찾아 재호출한다.
- 분기보고서(1·3분기): 자산총액 5천억원 미만 상장사는 검토 의무가 없어 첨부가 없는 것이 정상이다. **이 경우에만** 사용자에게 본문 사용을 확인하고 `use_body=true`로 재호출한다.
- 본문으로 만든 결과에는 주석 하이퍼링크가 없다는 점을 사용자에게 알린다(본문에는 주석번호 열이 없어 링크 0개가 정상이다).

**`scope_not_in_document`** — 선택된 문서에 요청 범위가 없다. 반환된
`available_scopes`를 사용자에게 보여주고, 그 범위로 다시 만들지 확인한 뒤
재호출한다. 다른 접수번호를 쓰는 것도 대안이다.

**`no_financial_statements`** — 같은 문서로는 재시도가 무의미하다. 반환된
`documents` 제목 목록을 보고 다른 접수번호를 찾거나, 사용자에게 사유를
안내한다. 필요하면 `get_audit_opinion`으로 감사의견을 조회해 **확인된 사실
기반**으로 안내한다(예: 의견거절·감사범위제한으로 재무제표 미공시). 추측하지
말고, 원인을 특정할 수 없으면 "원인 특정 불가, 원문 직접 확인 필요"라고 솔직히
안내한다.

**`verification_failed`** — `failures` 목록을 확인한다. **검증에 실패한 파일은
반환되지 않으며, 어떤 경우에도 사용자에게 전달하지 않는다.**

**`invalid_rcept_no` / `invalid_output_dir`** — 입력값을 고쳐 재호출한다.

**`dart_api_error`** — DART가 오류를 반환했다(접수번호 부재, 인증키, 호출 한도
등). `status`/`message`를 사용자에게 그대로 안내한다.

**`internal_error`** — 예기치 못한 실패다. `stage`가 실패 단계를 알려준다.

- `download`: DART 통신 실패(타임아웃·5xx). 잠시 후 같은 인자로 1회 재시도할 수 있다.
- `parse` / `build` / `verify`: 이 문서로는 재시도가 무의미하다. 다른 접수번호를 찾거나 사용자에게 사유를 안내한다.

`message`에는 예외 종류만 담긴다(원문·인증키가 새지 않도록 의도적으로 제한).

## 반드시 지킬 것

- **원문 content를 요청하거나 대화에 출력하지 않는다.** 공시 원문 조회 도구를 직접 부르지 않는다.
- **중간 XML을 읽거나 저장하지 않는다.** 서버가 메모리에서 처리한다.
- **중간 모델 JSON을 만들지 않는다.**
- **검증에 실패한 파일을 전달하지 않는다.**
- MCP 도구가 반환한 최종 Excel만 전달한다.
- **특정 기업 하드코딩 금지**: 회사별 예외 처리를 넣지 말 것.

## 출력 명세

- 재무제표별 시트(예: 연결재무상태표, 연결포괄손익계산서, 연결자본변동표, 연결현금흐름표) + 마지막에 `주석` 시트.
- 주석번호는 표의 **우측 끝 열**로 이동, "4,21" 같은 복수 참조는 **번호마다 개별 셀**로 분리.
- 각 숫자 주석번호는 파란색(0000FF)/밑줄 하이퍼링크로 `주석` 시트의 해당 주석 **제목 행**(`N.` 으로 시작)으로 이동.
- 테두리는 **실제 표 범위에만** 적용. 제목/회사명/기간/단위(프리앰블)와 문단에는 테두리 없음.
- freeze panes, auto filter **사용 안 함**.
- 정수 금액은 숫자 셀(`#,##0;(#,##0)` 서식), 괄호 숫자는 음수로 변환.

## 서버가 수행하는 검증

1. 시트 구성: 재무제표 시트들 + `주석`이 원문과 일치.
2. 재무제표 수: 원문과 동일, 4종 미만이면 실패(4종이면 손익/포괄손익 통합 형식 경고).
3. 프리앰블(제목/기수/회사명/단위)이 원문과 일치.
4. 주석 번호 연속성: 중복/역순/번호 누락(병합 의심) 탐지, 참조된 주석이 모두 존재.
5. 주석 링크: 모든 숫자 주석번호가 개별 셀 + 하이퍼링크, 링크가 `주석` 시트의 정확한 제목 행을 가리키는지, 파랑/밑줄 서식, 링크 수가 원문 기대값 이상인지. 정기보고서 본문으로 만든 경우는 주석번호 열이 없으므로 링크 0개가 정상이다.
6. freeze panes / auto filter 부재.
7. **글자 단위 완전성**: 원문 섹션의 모든 글자(공백 제외) 출현 횟수와 결과물의 글자 출현 횟수를 전수 대조 — 번호 체계가 안 바뀌는 내부 문단/셀 누락까지 검출. 이미지 파일명·캡션 등 엑셀로 옮기지 않는 요소만 집계에서 제외.

이 검증을 모두 통과한 파일만 반환된다.

## 참고

- 대용량 문서(수 MB)는 서버 파싱에 시간이 걸릴 수 있다. 도구 응답을 기다린다.
- 연결/별도 판별 근거: 감사·검토보고서 첨부는 `(첨부)연결재무제표` / `(첨부)재무제표`, 정기보고서 본문은 `연결재무제표`+`연결재무제표주석` / `재무제표`+`재무제표주석` 제목으로 구분된다. 서버가 처리하므로 스킬이 직접 판단할 필요는 없다.
